# 提示词规范：把风格描述翻成渲染规格

> 这份文件解决一个问题：通用的视频风格描述是**给画师或生成模型看的**，
> 而 DeepSeek 拿到手要写的是**能跑出画面的程序**。同一句话，前者让它"想象"，后者必须让它"实现"。
> 差别是决定性的：同一个风格，只写形容词大约 5 分，写足坐标、色值、时间轴能到 8 分以上。

---

## 一、原提示词为什么不能直接用

拿 66 号「终端 / ASCII CRT」的原文举例：

> 做一段终端风格动画：画面上所有东西都是等宽字符，单色绿色荧光、扫描线和光晕，像在老 CRT 显示器上运行。

这句话人一看就懂，但交给模型写代码会缺 8 类信息：画布多大、用什么技术、字符网格多少列、绿是什么绿、扫描线多粗、光晕怎么叠、6 秒里发生什么、怎么算做完了。

**实测结果**：直接用风格名 + 几个形容词，第一次产出必然是"黑底 + 绿色文字 + 几条横线"的通用动画（见 REPORT 的 v1）。补上规格后，同一路线一次到 8/10（见 REPORT 的 v3）。

### 一句话原则

> **形容词是给人验收的，参数才是给机器执行的。**
> 提示词里每个形容词，都必须能落到一个数值、一个图层或一个函数。

---

## 二、提示词的六段式结构（强制）

一份可用的提示词必须按下面六段写，缺任何一段都会显著掉质量。

| 段 | 作用 | 缺了会怎样 |
|---|---|---|
| ① 任务与交付物 | 一支多长、什么画幅、给谁看、一句话风格 | 模型自由发挥，跑偏 |
| ② 交付契约 | 技术栈 + 代码接口 + 确定性规则 | 出来的东西不能逐帧渲染，或每帧都不一样 |
| ③ 版面规格 | 分区块坐标表 | 内容全堆左上角，下半屏空白（实测） |
| ④ 视觉 DNA | 3–5 个标志元素，每个都带参数 | 退化成"通用扁平风" |
| ⑤ 时间轴 | 分镜表 + 缓动 | 画面静止或乱动，没有节奏 |
| ⑥ 验收 | 自检项 + 抽帧时间点 | 模型自己认为"完成了"，实际不能看 |

## 三、②交付契约：写死接口

所有场景统一用**单文件 HTML + 定点渲染**契约，这样任何模型产出的东西都能被同一套工具渲染、比对、验收。

```html
<!DOCTYPE html>
<html lang="zh"><head><meta charset="utf-8"><style>
  html,body{margin:0;background:#000;overflow:hidden}canvas{display:block}
</style></head><body>
<canvas id="c" width="1920" height="1080"></canvas>
<script>
  const W = 1920, H = 1080;
  window.__meta = { width: W, height: H, fps: 24, duration: 6 };
  const ctx = document.getElementById('c').getContext('2d');

  function seek(t) {          // t = 秒，唯一输入
    // 每一帧都从这里完整重绘；同一 t 必须得到同一像素
  }

  window.seek = seek;
  window.__ready = true;
  seek(0);                    // 先画一帧，避免首帧空白
</script></body></html>
```

**四条硬规则**（写进提示词原文，不要省）：

1. **确定性**：同一 `t` 必须得到同一像素。禁用 `Math.random()`、`Date.now()`、`performance.now()`、`requestAnimationFrame` 驱动的状态。
   随机数用自带种子的 `mulberry32(seed)`。
2. **无外部依赖**：不联网、不引用 CDN、不加载外部图片/视频/字体文件（字体用系统白名单，见第五节）。
3. **一次绘制**：`seek(t)` 内部从零重绘，不依赖上一帧状态（否则跳帧、对比失败）。
4. **预烘焙**：静态部分（纸张纹理、地形、字形）在脚本初始化时算一次，`seek` 里只做合成。

## 四、③版面规格：必须给坐标表

实测教训：不给版面，模型会把所有内容按"从上往下堆"排版，结果上半屏挤满、下半屏全黑。

提示词里直接写：

```text
版面（1920×1080，外边距 56）：
- 顶栏：y 56–102，半透明底条，左标题右时间
- 主信息区：x 56–1215，y 186–486，12 行 × 25px
- 右侧监控栏：x 1394–1864，y 168–546
- 波形区：x 56–1215，y 505–660
- 大字标：居中，y 700–920，每行高 33
- 底部状态条：y 1034–1080，满宽反白
禁止元素跨越上述区块边界。
```

三个要点：

- 给**坐标 + 区间的宽度**，不只给"上面/下面"。
- 给**字级层级**（标题 17px / 正文 18px / 字标 29px），字号决定信息密度。
- 明确"禁止跨区"，否则波形会压住右侧数据（实测发生过）。

### 双画幅：16:9 与 9:16 必须各排一套

同一支片子要出 1920×1080 和 1080×1920 两版。**不是缩放**——横屏版面塞进竖屏会把字压小、留白失衡。

提示词里写成**两张版面表**，让模型按画幅取表：

```js
const ASPECT = new URLSearchParams(location.search).get('aspect') || '16:9';
const LAYOUT = {
  '16:9': { W: 1920, H: 1080, M: 56, log: { y: 130, row: 25 }, wave: { y: 505, h: 152, rows: 8 } },
  '9:16': { W: 1080, H: 1920, M: 44, log: { y: 160, row: 24 }, wave: { y: 918, h: 228, rows: 12 } },
};
const L = LAYOUT[ASPECT];
```

三条硬要求：

1. 竖屏纵向空间比横屏多约 45%，**允许追加区块填满底部**（66 号在竖屏里加了十六进制转储区），不许留大片空白。
2. 字号、行距、列数**按画幅分别给**，不要写死一套再等比缩放。
3. 两版**各自独立过验收**，任何一版不合格，这条风格就不算完成。

渲染器对应参数：`node render.mjs --scene x.html --aspect 9:16 --out out/x-portrait`。

## 五、④视觉 DNA：把形容词翻译成参数

这是全套文档里最值钱的一节。翻译规则三条：

| 原文类型 | 翻译成 | 例子 |
|---|---|---|
| 名词（材质、物体） | 图层 + 几何生成方式 | "宣纸" → 纸色基底 `#F6F0E0` + 3200 条纤维短弧（alpha 0.008–0.03）+ 逐像素噪声 ±7 |
| 形容词（浓淡、粗细、软硬） | 数值区间 + 分布 | "墨分五色" → 5 档灰度 `#14161A / #2A2D33 / #4A4E55 / #737880 / #A8ADB4`，占比 5:4:3:2:1 |
| 动词（晕开、掠过、弹入） | 缓动函数 + 时长 + 曲线 | "弹入" → `easeOutBack，0.45s，过冲 8%` |

### 必须给出的四类参数

1. **色彩**：主色写十六进制；限定色数（"全片只用 3 色"比"色彩克制"有效 10 倍）。
2. **字**：字体名 + 字号 + 字重 + 颜色 + 逐字还是整行绘制（见第七节黑名单）。
3. **线/形**：线宽、圆角、描边还是填充、透明度区间。
4. **运动**：帧率（手绘感用 12fps 抽帧）、缓动名、节奏 BPM 或"每 N 帧一次"。

### 反例 → 正例

| ✗ 不能执行 | ✓ 可执行 |
|---|---|
| 单色绿色荧光 | 荧光绿 `#7EFF9E`，暗部 `#3A9658`，背景 `#04080A` |
| 扫描线和光晕 | 每 3px 一条 1.3px 黑线，alpha 0.15；辉光用 `blur(5px)` 叠一层 `lighter`，alpha 0.5 |
| 像老 CRT | 暗角 `radial(0→0.66 黑)`；刷新带每 6s 扫一次，宽 260px，alpha 0.05；亮度闪烁 ±2.8% |
| 所有东西都是等宽字符 | 网格 12×21px；方块字符逐字定点摆放，字宽 12.6px（见第七节） |

### 三个"看起来对、其实是错"的写法（实测踩过）

| ✗ 容易写成 | 为什么会错 | ✓ 应该写 |
|---|---|---|
| 固定 `cellW = 12.6` 逐字摆放 | 字宽大于字形宽度 → `█` 之间出现细缝，整块图形变网点 | 先用 `measureText('█')` 实测 advance，`cellW = w * 0.995` |
| `fillRect(x + i*cw, y, cw, ch)` | 小数坐标各自抗锯齿，相邻块之间留淡线 | `x0 = round(...)`, `x1 = round(...)`, 宽 = `x1 - x0` |
| 用 ASCII 艺术字做字标 | `╔╗║═` 是双线框线字符，在实心块里会飘出两条平行细线 | 用 5×7 像素字模，每格一个矩形，缩放不散 |

## 六、⑤时间轴：分镜表格式

不要写"有节奏地出现"，写表：

| 时间 | 内容 | 动效 |
|---|---|---|
| 0.0–0.6 | 顶栏 + 开机信息 | 直接出现，alpha 0→0.9 |
| 0.35–1.05 | 命令行逐字打出 | 32 字/秒，光标每 0.42s 闪一次 |
| 1.15–3.13 | 12 行日志 | 每行 0.18s 间隔，出现后 0.15s 内 alpha 爬到 1 |
| 0.9– | 波形 | 常驻，横向滚动 2.4 px/帧 |
| 3.0–3.4 | 大字标 | alpha 0→0.95，2.6 倍速爬升 |
| 全程 | 刷新带 | 6s 扫过一屏 |

**节奏的两个经验值**：

- 6 秒片最多 3 个信息高潮，多了记不住。
- 每 0.15–0.2s 给一次视觉变化（新行、新元素、位移），低于这个频率会觉得"卡住了"。

**三条实测硬约束**（都对应过翻车，写进提示词）：

1. **进场总时长 ≤ 时长 1/5**。6 秒片子入场别超过 1.2 秒。92 号初版把三张卡排到 1.0/1.35/1.65s，
   前 1 秒几乎是空屏——观众第一眼看到的是"没加载出来"。
2. **坐标轴、刻度、图例、数据同一时刻出现**。柱子还没长就先画轴线，1.35–1.8s 只剩一条基线和
   三个悬空的时间刻度，看着像故障。
3. **中文标题不用遮罩上推**。`riseIn` 的遮罩会把中文字切成"只剩横笔画"的一条，改用淡入 + 上浮
   （`mask:false`）；拉丁字母才适合遮罩。

## 七、黑名单（写进提示词，逐条禁止）

| 禁止 | 原因 | 替代 |
|---|---|---|
| `Math.random()` | 每帧不同，画面闪烁 | `mulberry32(固定种子)` |
| `Date.now()` / `requestAnimationFrame` 自驱 | 渲染不可复现 | 只用传入的 `t` |
| 外部 URL / CDN / 图片 | 渲染环境可能断网 | 画出来 |
| 生成式模型（Seedance / Kling / Runway） | 本技能范围外 | — |
| 只写风格名 | 退化成通用扁平风 | 3–5 个标志元素 + 参数 |
| `ctx.fillText` 直接画方块字符（`█ ░ ╔`） | 系统字体回退→字宽漂移→整块错位 | 逐字定点：`x + i * cellW` |
| 每帧 `new ImageData` / 重建大对象 | 帧耗时 > 100ms | 初始化时烘焙 |
| 逐帧 `createRadialGradient` | 同上 | 预生成渐变对象或预烘焙图层 |

## 八、⑥验收：让模型自己先过一遍

提示词结尾必须附这段（原样抄）：

```text
交付前自检，逐条回答：
1. 同一 t 渲染两次，像素是否完全一致？
2. 是否有任何元素超出你写的版面坐标？
3. 6 秒里每一帧是否都有可见变化？列出 t=0/1.5/3/4.5/5.9 各自画面里新增了什么。
4. 有没有出现黑屏帧、全白帧、纯色帧？
5. 方块字符是否逐字定点？文字是否被裁切？
6. 单帧绘制耗时是否 < 16ms？（console.time 实测并报数）
7. 是否用了黑名单里的任何一项？逐条核对。
```

## 九、对照：同一风格，两种写法

| 风格 | 提示词写法 | 结果 |
|---|---|---|
| [66 终端 / ASCII CRT](styles/66-crt.md) | 六段齐全，版面给了坐标表，字符逐字定点 | 一次成型，144 帧 19s 渲完 |
| 中国水墨 / 写意 | 只有风格描述 + 材质形容词 | 不成立：墨的浓淡不在几何，而在笔的物理 |

水墨这类笔触风格是"形容词不可执行"最典型的证据——用程序近似笔触，代码会依次踩进"渐变当材质""实心当墨块""阈值化当墨韵""擦除当飞白"四个坑。**写不出参数的风格，就不要用纯代码做**。
