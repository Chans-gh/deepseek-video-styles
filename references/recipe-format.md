# 配方格式：一份风格文档该写什么

> 34 份配方的字段与顺序固定。照这个写，模型能直接照做；跨风格比对时也不用重新找信息。

---

## 骨架

````markdown
# <编号> <中文名> · <English Name>

**技术栈** 一句话说清用什么画、关键手法
**画幅** 16:9（1920×1080）+ 9:16（1080×1920）

| 参数 | 16:9 | 9:16 |
|---|---|---|
| <区块> | x,y / w×h r圆角 | x,y / w×h r圆角 |

**时间轴**：0.1 <事件> → 0.6 <事件> → 1.2 <事件> → …（一直写满 duration）

**注意事项**

1. <现象 → 原因 → 怎么改>

**规格卡**

```text
版面：画布尺寸、版心、基线、栏数
颜色：每个色值都写出来
动作：按时间顺序，带缓动名
禁止：这个风格不能出现的东西
```
````

---

## 各节要求

| 节 | 必填 | 要求 |
|---|---|---|
| 标题 | 是 | `编号 中文名 · English`，编号与 `styles.md` 目录一致 |
| 技术栈 | 是 | 写到手法级。不写"Canvas 2D"，写"Canvas 2D（Catmull-Rom 过点样条 + 弧长切片）" |
| 参数表 | 是 | **横竖两列都要给实数**，坐标直接可用，不许留占位 |
| 时间轴 | 是 | 一行流，写满 `0 → duration`；末段不能空 |
| 注意事项 | 是 | 每条都是"现象 → 原因 → 做法"，只写真的踩过的 |
| 规格卡 | 是 | 纯文本，可整段粘进提示词；含版面 / 颜色 / 动作 / 禁止 |

---

## 参数怎么给

- 坐标一律 `x,y`（区块左上角），尺寸 `w×h`，圆角 `r`。
- 字号写 `px`，基线写 `baseline y`。
- 时间轴用秒，一位小数就够。
- 两列必须真的分别算过——竖屏不是横屏缩放，列数和行高都会变。

---

## 写作纪律

1. **参数优先**：能写数字就不写形容词。
2. **一票否决**：出现"有质感""稍微""大概"这类不可验收的词，退回重写。
3. **可复制**：规格卡必须自包含，不依赖读者翻别处。
4. **留坑**：踩过的坑要写进注意事项——这是复用价值最高的部分，比参数表更容易被忽略。

---

## 加一份新风格前，先答这三个问题

1. **它和第 34 份的差别是结构还是配色？** 只有配色不同就不算新风格，改配方里的色值即可。
2. **标志元素能不能数出来？** 能数出 3–5 个可参数化的元素（形状、比例、动效），就能做。
3. **有没有一处"程序做不到"？** 笔触、真实光影、实拍质感——有就换风格，不要硬凑（见 `prompt-spec.md` 第九节）。
